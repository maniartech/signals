> **Status:** This document reflects the agreed v1.4.0 direction: the
> correctness work from [PR #14](https://github.com/maniartech/signals/pull/14)
> (partially accepted) **plus** a proper lock-free rewrite that restores a

> The authoritative changelog is [RELEASENOTES.md](RELEASENOTES.md).

> must be reflected here and kept current. Design records under `docs/design/` (e.g.

## Objectives

Version 1.4 is a **correctness + verified-performance release**: fix the behavioral
bugs found during audit, make the async/sync contracts honest and predictable, replace
the removed performance machinery with a lock-free copy-on-write core, and document the
library as it actually behaves — with every performance number backed by a committed,
reproducible benchmark.

**Philosophy**: Ship something correct, honest, *and* fast. PR #14's lesson was not
"performance is bad" — it was "don't ship claims you can't reproduce." So v1.4 keeps
the correctness fixes, rebuilds performance via lock-free copy-on-write, and lets
`benchstat` output — not marketing — decide what the README is allowed to claim.

> ⚠️ **v1.4.0 contains a breaking runtime change.** `AsyncSignal.Emit` is now truly
> fire-and-forget (returns immediately). Code still compiles, so the change is
> silent — callers who relied on the old blocking behavior must switch to
> `TryEmit`. See [RELEASENOTES.md](RELEASENOTES.md) and the README migration note.

### Primary Goals

0. **Lock-free copy-on-write core**: replace `sync.RWMutex` with an immutable listener
   slice behind `atomic.Pointer`, writers serialized by a mutex (lock-free reads,
   locked writes). Eliminates the per-emit snapshot copy and reader contention.
   Performance claims gated on measured before/after numbers.

1. **Correct, honest semantics**: `AsyncSignal.Emit` is fire-and-forget;
   `SyncSignal.Emit` invokes error-returning listeners (discarding errors);
   `TryEmit` stops on first error/cancel. Canceled contexts skip all listeners.

2. **Zero-value safety**: `var sig signals.SyncSignal[int]` / `AsyncSignal[int]`
   is usable without a constructor (lazy `sync.Once` init).

3. **Bug fixes**: keyed removal no longer drops unkeyed listeners; `GrowthFunc` is
   actually honored (was dead code); race/staticcheck findings resolved.

4. **Safe escape hatch + panic policy**: `TryEmit` for callers that need the old
   blocking behavior; `SetPanicHandler` replaces silent `recover()`.

5. **API ergonomics (small, low-risk)**: one-time listeners
   (`AddOnce`/`AddOnceWithKey`) and key introspection (`Keys`/`HasKey`) — done;
   `AddListenerWithErr` on async is **planned for Phase 4** (per ADR 0001 §B3), *not*
   yet shipped (sync `AddListenerWithErr` is done).

6. **Documentation that matches reality**: README, godoc, and release notes describe
   actual behavior; the migration path from v1.3.x is documented honestly.

7. **Bounded async dispatch (safety valve, not a throughput lever)**: add
   `SignalOptions.MaxConcurrent` to bound *concurrent* handlers via a counting
   semaphore (per [ADR 0001](docs/design/0001-async-dispatch-and-error-model.md)).
   Unbounded by default; excess parks (never dropped, caller never blocked); no
   lifecycle/`Close()`. It makes async resource use **bounded and predictable** — it is
   explicitly **not** a throughput optimization and must not be benchmarked or claimed
   as one.

8. **Verified concurrency**: property-based + native fuzz testing of the lock-free core,
   on top of race + stress coverage, to prove the rewrite's invariants.

### Explicitly NOT in v1.4 (moved to v1.5+)

- **Metrics**: `Stats()`, Prometheus exporter, `Metadata()` introspection — observability
  is its own release; the v1.4 core stays lean. (This is the *only* item deferred to
  v1.5; lock-free, bounded async dispatch, and property/fuzz testing are all in v1.4.)

## Functional Requirements

### 0. Lock-Free Copy-on-Write Core
**Priority:** HIGH
**Status:** **Implemented ✅ (Phase 2)** — the defining engineering work of v1.4; `-race`
clean, measured (see Success Criteria below and `bench/`).

**Original State (now replaced):** `BaseSignal` guarded `[]keyedListener[T]` with
`sync.RWMutex`; every `Emit`/`TryEmit`/`dispatch` took an `RLock` and copied the slice
into a snapshot before iterating. The copy cost was paid on the hot *read* path. This is
the RWMutex baseline captured in `bench/baseline.txt`.

**Target:** Store listeners as an **immutable** slice behind `atomic.Pointer[[]keyedListener[T]]`.
Reads (Emit) do a single atomic load and iterate directly — no lock, no copy, no alloc.
Writes (Add/Remove/Reset) take a `sync.Mutex`, build a new slice, and atomically swap it
in (copy-on-write). This is "lock-free reads, locked writes" — **not** full CAS-loop
lock-free; do not attempt the latter.

**Requirements:**
- Replace the `RWMutex` + per-emit snapshot with `atomic.Pointer` + write-mutex COW.
- Preserve all existing semantics byte-for-byte: ordering, keyed dedup map, `keyed`
  flag, `GrowthFunc` behavior, zero-value safety, context/cancel rules.
- Public API unchanged; all existing tests pass unmodified.
- The keyed-dedup map must stay consistent with the swapped slice (rebuild or guard
  under the write mutex).

**Success Criteria (gate every perf claim on these):**
- `go test ./... -race` passes 100%. ✅ **met**
- `benchstat` shows the multi-listener path drops its per-emit allocation. ✅ **met**
  (10-listener: 210.9 ns/416 B/1 alloc → 69.8 ns/**0 B/0 alloc**).
- A concurrent-sync benchmark demonstrates near-linear scaling vs the RWMutex baseline.
  ✅ **met** (concurrent: 49.8 ns → **3.0 ns**, −94%).
- Sync single-listener path: **target ~10–12 ns was NOT met** — measured ~17.8 ns,
  essentially unchanged, because the prior code already had a zero-alloc 4-element stack
  fast path. ⚠️ **not met (documented honestly in `bench/README.md`)**. This is acceptable:
  the lock-free win is in the multi-listener and concurrent paths, not single-listener.
- **Honesty rule:** no performance number reaches the README until it is produced by a
  committed benchmark and reproducible via `go test -bench`. Async numbers must be
  labeled as dispatch rate (goroutine-per-listener), not listener completion.

### 1. Correct Emit / Cancel / Error Semantics
**Priority:** HIGH
**Status:** Implemented ✅ (PR #14 + maintainer fixes)

**Requirements:**
- `AsyncSignal.Emit` schedules each listener in its own goroutine and returns
  immediately (does not wait).
- `AsyncSignal.TryEmit` schedules listeners concurrently and blocks until all
  complete.
- `SyncSignal.Emit` invokes both plain and error-returning listeners, discarding any
  returned errors.
- `SyncSignal.TryEmit` invokes listeners sequentially and stops on the first error or
  canceled context, returning that error.
- A context that is already canceled causes all `Emit`/`TryEmit`/`TryEmit`
  variants to skip every listener.

**Success Criteria:**
- Each rule above is covered by a dedicated, non-flaky test (no fixed-sleep / wall-clock
  assertions; use channels, `<-ctx.Done()`, polling with deadlines).
- `go test ./... -race` passes.

### 3. Panic Policy
**Priority:** HIGH
**Status:** Implemented ✅

**Requirements:**
- `signals.SetPanicHandler(func(recovered any))` configures how recovered async
  listener panics are reported. Default logs via the stdlib `log` package. Passing
  `nil` discards. Implementation is race-safe (`atomic.Pointer`).
- Panics are never swallowed silently.
- **The failure path is itself failure-safe (FR-8 I14):** the panic handler is the
  *last* line of defense, so it must be unbreakable. A panic raised by the panic
  handler **itself** is recovered and discarded rather than propagating out of the
  handler goroutine — where, unrecovered, it would crash the whole process and defeat
  panic isolation. We discard (not re-report) the secondary panic to avoid unbounded
  recursion; the documented contract is that the handler must not panic, and if it
  does we contain it. The same isolation applies to `OnError` sinks (a panicking sink
  is recovered and does not stop the others) and to one-shot wrappers.
- **One-shot panic policy:** an `AddOnce` handler is *consumed on attempt* — it is
  marked fired and removed before it runs, so a panic on its single invocation is not
  retried on a later emission. (Async recovers the panic and routes it to the handler;
  sync propagates it to the `Emit` caller, like any sync listener.)

**Success Criteria:**
- A panicking listener does not crash other listeners; the configured handler is
  invoked; the default and `nil` cases are tested.
- **I14 is proven at all three sites:** a panicking `OnError` sink, a panicking panic
  handler, and a panicking one-shot handler each leave the process alive, siblings
  running, and (under a bound) no slot leaked.

### 4. Bug Fixes
**Priority:** HIGH
**Status:** Implemented ✅

- `RemoveListener("")` no longer removes unkeyed listeners — keyed listeners are
  tracked with an explicit `keyed bool`.
- **Empty-string key = unkeyed (refined in Phase R, per the FR-9 contract):** adding a
  listener with an explicit `""` key is treated as **unkeyed** (not a distinct removable
  key). Consequently `HasKey("")` is always `false`, `Keys()` never contains `""`, and
  `RemoveListener("")` is a no-op returning `-1`. *(This refines the earlier PR #14
  behavior, where an explicit `""` key was a removable key but was already hidden from
  `Keys()` — an internal inconsistency now resolved uniformly.)*
- `SignalOptions.GrowthFunc` is honored when the subscriber slice grows (was stored
  but never called).

**Success Criteria:**
- Regression tests cover keyed vs unkeyed removal and a custom `GrowthFunc` being
  invoked on growth.

### 7. Bounded Async Dispatch — semaphore safety valve
**Priority:** MEDIUM
**Status:** Not Implemented (0%) — design **LOCKED**. This section is the canonical
statement; [ADR 0001](docs/design/0001-async-dispatch-and-error-model.md) is the
subordinate record holding the full rationale (the earlier "worker pool / performance
lever" framing has been corrected throughout this doc).

**Current State:** `AsyncSignal` spawns one goroutine **per listener per emit**, unbounded.
Under sustained overload (fast emitter + slow listeners) goroutines accumulate without
limit — the classic event-system meltdown.

**Target (per ADR 0001):** Bound how many handlers run **concurrently** using a counting
**semaphore** — *not* a persistent worker pool. `Emit` spawns one dispatcher goroutine and
returns immediately; each handler runs independently/concurrently; when a `MaxConcurrent`
bound is hit, excess handlers **park** (cheaply) until a slot frees — **never dropped, and
the caller is never blocked.**

```go
type SignalOptions struct {
    InitialCapacity int                // existing
    GrowthFunc      func(int) int      // existing
    MaxConcurrent  int                // NEW: bounds CONCURRENT handlers; 0/unset = unbounded
}

func DefaultMaxConcurrent() int       // recommended bound = 2*runtime.NumCPU(); NOT auto-applied
```

**Requirements:**
- Add `MaxConcurrent` to `SignalOptions`. **Default is UNBOUNDED** (`0`/unset → today's
  goroutine-per-handler behavior). Bounding is an **informed opt-in** — a default bound is
  rejected because it can **silently starve long-running listeners** (only N run, the rest
  never start). `DefaultMaxConcurrent()` (= `2*NumCPU`) is the recommended value, not a
  default.
- Bound via a counting semaphore (`slots chan struct{}`). **No persistent workers, no
  `Close()`, no lifecycle** — the semaphore is GC-friendly.
- `Emit` = `go dispatch()` (fire-and-forget, caller never blocks even with a bound).
  `TryEmit`/`TryEmit` share `dispatch` and obey the same bound.
- Preserve panic recovery via `SetPanicHandler` and context-cancel behavior.
- No drop/overflow policy in v1.4 (excess parks). Explicit drop/block/error policies are
  **Future Hardening H1**, not v1.4.
- **Slot release on every path (I13):** acquire/release must be `defer`-paired so the slot
  is released exactly once on normal return, returned error, **and recovered panic**;
  ordered so the recover cannot bypass the release.
- **`TryEmit` / `TryEmit` ctx-liveness:** the **waiter** MUST return when `ctx`
  is canceled or its deadline expires, even if a listener is still running (returning
  `ctx.Err()`, joined into the aggregate for `TryEmit`). A single hung/slow listener
  MUST NOT block the waiter past the caller's deadline. (Go cannot force-cancel the detached
  listener goroutine; the guaranteed property is the *waiter's* liveness.)
- **Cancellation of parked dispatch:** if `ctx` is canceled mid-dispatch, the dispatcher
  stops acquiring slots and skips all not-yet-started handlers; a handler blocked acquiring
  a slot aborts the acquire (`select` on `slots` vs `ctx.Done()`) rather than starting after
  the deadline.
- **`OnError` execution contract:** sinks run on the handler's own goroutine **after the
  slot is released** (so a slow/blocking sink cannot starve the pool); a panic inside a sink
  is recovered and routed to `SetPanicHandler` and does not skip remaining sinks.
- **`TryEmit` aggregation:** errors are collected race-free (per-handler result slot
  indexed by registration position) and joined via `errors.Join` in **deterministic
  registration order** (not completion order), so the aggregate error is reproducible.
- **Naming decision — RESOLVED ✅:** the option is named **`SignalOptions.MaxConcurrent`**
  with helper **`DefaultMaxConcurrent()`** (= `2*NumCPU`). The earlier candidate
  `WorkerPoolSize` was **rejected** because the design is a counting semaphore, not a worker
  pool: there are no persistent workers and no `Close()`, so "pool" would plant a wrong
  mental model and imply a lifecycle that does not exist. `MaxConcurrent` reads exactly as
  the behavior — "at most N handlers run at once." Decided while free to choose (Phase 4 not
  yet built, no dependents); it is permanent public API once shipped.
- Document the two risks (A5): **starvation** of long-running listeners under a bound, and
  **reentrancy self-deadlock** (a handler that `TryEmit`s on its own bounded signal).
- **Godoc must state the backlog caveat:** the bound caps *concurrent execution*, not the
  *backlog* — under sustained overload, parked dispatch grows unbounded (hard ceiling is
  opt-in H1, post-v1.4). Users enabling a bound for "safety" must not assume memory is
  bounded.

**Success Criteria:**
- With `MaxConcurrent = N`, at most `N` handler goroutines run concurrently (proven, not
  assumed — see FR-8 I8); with no bound, dispatch is unbounded and **never starves**.
- `Emit` returns without waiting in all configurations (FR-8 I9); `-race` clean; no
  goroutine leaks under the stress test (FR-8 I12).
- **Honesty rule (reframed):** this is a **bounded-resource safety valve, not a throughput
  optimization.** It adds a dispatcher goroutine + semaphore ops and will **not** beat
  goroutine-per-listener on a raw-speed benchmark. Benchmark/document it as *predictable,
  bounded resource use under load* — never as a speed win. The `MaxConcurrent` value is
  documented with sizing guidance (tie to the slowest dependency, e.g. DB connection limit;
  never to the listener count).

#### Prior art: why a pool existed, why PR #14 removed it, why we bring it back

**A pool existed on `master`** (removed in PR #14 commit `746bcd5`): `AsyncSignal.Emit`
used a bounded `workerPool chan *emitTask`, a `sync.Pool` for snapshot/task reuse, and a
single-listener "zero-allocation fast path" — all to support the old README's
*"sub-10ns, zero-allocation"* claims.

**PR #14 was right to remove *that* pool.** Its removal reasoning (reconstructed from the
diff + commit titles; the PR wrote no long justification):
1. **It blocked.** The old `Emit` ended with `wg.Wait()` and a *bounded* channel send
   (`s.workerPool <- task`) blocks the caller when saturated — fundamentally incompatible
   with the new fire-and-forget `Emit`.
2. **Deadlock risk** — commit `9187cd9` ("Fix sync deadlock risk and async snapshot");
   bounded channel + reentrant emits could wedge.
3. **The claim it served was false** — async allocates inherently (goroutine per
   listener); the audit tests (`0c05756`) proved the "zero-alloc" story didn't hold.
4. **Lifecycle complexity** — `sync.Once` init, two `sync.Pool`s, a size threshold, and
   GC-based shutdown, versus a trivial `go func()`.

**Strong reasons to reintroduce a pool in v1.4 (a *different*, fire-and-forget-native one):**
1. **Unbounded goroutines = no backpressure = the #1 production failure mode.** Today a
   fast emitter with slow listeners spawns goroutines without limit — memory blows up and
   the scheduler thrashes under load. This is the classic event-system outage. A bounded
   pool is the *only* control point that prevents it. For a library positioned at
   HFT/real-time/embedded, "spawn as many goroutines as the load demands" is a
   non-starter — those domains require **bounded, predictable** resource use.
2. **Bounded, predictable resource use — a *safety* property, not a *speed* one.**
   *(Reframed per ADR 0001.)* The semaphore caps concurrent handler execution so a fast
   emitter + slow listeners cannot exhaust the process. It is **not** a throughput
   optimization — it adds a dispatcher goroutine + semaphore ops and will not beat
   goroutine-per-listener on ns/op. The value is survival under load, not speed.
3. **Operator control.** `MaxConcurrent` lets users tune the concurrency ceiling to their
   slowest dependency (e.g. DB connection limit) instead of being at the mercy of
   fan-out × emit-rate.
4. **It restores the capability honestly.** Bounded async dispatch — earned by proving the
   bound holds (FR-8 I8), built non-blocking and `Close()`-free, and **not** sold as a
   throughput or zero-alloc win.

**Hard design constraints (locked in ADR 0001 — the mistakes we must NOT repeat):**
- **`Emit` must never block the caller** — achieved by `go dispatch()`; any slot parking
  happens in the background dispatcher, never on the caller's thread. No drop policy in
  v1.4 (excess parks); drop/block/error policies are Future Hardening H1.
- **Reentrancy** — a handler that emits fire-and-forget on the same signal is safe; a
  handler that `TryEmit`s on its own *bounded* signal can self-deadlock (documented
  caveat A5), not silently prevented.
- **No lifecycle** — counting semaphore, GC-friendly; **no `Close()`, no `Reset`/finalizer
  shutdown.** (Reverses the earlier "deterministic shutdown tied to Reset/close" note.)
- **Judged on the bound, not on speed** — ships when the concurrency bound is *proven*
  (FR-8) and resource use is predictable; it is explicitly **not** gated on "beating
  goroutine-per-listener," which it will not do.

### 8. Verified Concurrency — the Proof Standard (Property + Fuzz + Stress)
**Priority:** HIGH (this is what earns the "robust" claim)
**Status:** Partial (40%) — race + concurrent benchmarks exist; property/fuzz/stress not yet

**Principle:** *Robustness is not designed in, it is proven.* No invariant of the
lock-free core or the async dispatcher may be *assumed*; each must be **mechanically
verified** by a committed test that an adversary (fuzzer, race detector, stress load)
has tried and failed to break. A claim of "military-grade / mission-critical
robustness" for the signaling primitive is earned **only** when every item in this
section is green and reproducible in CI — not before. This is the same honesty rule
applied to performance (FR-0), now applied to correctness.

This section is the authoritative definition of "proven" for v1.4. It is a **hard
release gate**: v1.4.0 does not tag until §8 passes in full.

#### 8.1 Invariants that MUST be proven

Every invariant below must have at least one dedicated, deterministic test. Invariants
marked **(core)** apply to the lock-free copy-on-write core (FR-0, built); those marked
**(async)** apply to the dispatcher + error model (FR-7/ADR 0001, to be built).

- **I1 — Count integrity (core):** `Len()` always equals the number of live
  registrations; duplicate keyed add returns `-1` and is a no-op; removing an absent
  key returns `-1` and is a no-op.
- **I2 — Introspection consistency (core):** `HasKey(k)` and `Keys()` agree with the
  set of live keyed listeners at every step (internal/auto keys and empty keys omitted
  from `Keys()`).
- **I3 — No-call-after-remove (core):** once removed, a listener is never invoked by any
  subsequent emission.
- **I4 — All-live-receive (core):** every emission invokes exactly the set of
  currently-live listeners — no misses, no extras, no duplicates.
- **I5 — No corruption under concurrency (core):** arbitrary concurrent
  add/remove/emit/reset interleavings never race, panic, deadlock, or corrupt state.
- **I6 — Exactly-once (async/core):** an `AddOnce` listener fires exactly once even
  under many simultaneous emissions, then auto-removes.
- **I7 — Panic isolation (async):** a panicking handler never crashes the process and
  never prevents sibling handlers from running; the recovered value reaches the
  configured `SetPanicHandler`.
- **I8 — Bounded concurrency (async):** with `MaxConcurrent = N`, at most `N` handler
  goroutines run concurrently across all in-flight emissions; with no pool, dispatch is
  unbounded and **never starves** a listener.
- **I9 — Fire-and-forget integrity (async):** `Emit` returns without waiting for
  handler completion in all configurations (pool or no pool).
- **I10 — Wait/aggregate correctness (async):** `TryEmit` returns only after all
  handlers of that emission complete; `TryEmit` returns the `errors.Join` of
  every handler error and `nil` iff all succeeded.
- **I11 — Error routing (async):** an error returned by an `AddListenerWithErr` handler
  on the `Emit` path reaches every registered `OnError` sink; none are dropped silently.
- **I12 — No goroutine/memory leak (async):** after emissions quiesce, goroutine count
  returns to baseline and memory does not grow unbounded across repeated cycles.
- **I13 — Slot release on every exit path (async):** every acquired semaphore slot is
  released **exactly once** on **all** handler exits — normal return, returned error, and
  **recovered panic**. The release `defer` must be ordered so a panicking handler cannot
  bypass it (release survives recover). *Test:* with `MaxConcurrent = N`, run N panicking
  (and N erroring) handlers, then assert full capacity is reusable (N fresh acquisitions
  succeed) and goroutines return to baseline — proving no slot leaked. This is the #1
  bounded-pool deadlock risk; it must be proven, not trusted to a `defer`.
- **I14 — Failure-path is failure-safe (async):** a panic inside an `OnError` sink, the
  `SetPanicHandler` callback, or an `AddOnce` wrapper must not crash the process, leak a
  slot, stop sibling handlers/sinks, or re-enter the panic handler unboundedly. *Test:* one
  dedicated case per site, under `-race` and the leak harness.
- **I15 — Ordering contract (core):** **Sync** `Emit`/`TryEmit` invoke listeners in
  current-slice order, which equals registration order **only until the first
  `RemoveListener`** (swap-remove may reorder thereafter — this caveat is **normative**,
  not a godoc aside). **Async** invocation/completion order is **explicitly unspecified**
  and must not be relied upon. *Test:* sync order stable absent removals; async asserts no
  ordering.
- **I16 — No silent drop under a bound (async):** with a bound and no cancellation, every
  dispatched handler eventually runs **exactly once** (excess parks, never dropped).
  *Test:* emit M ≫ N listeners under `MaxConcurrent = N`; assert all M ran.
- **I17 — Memory-model happens-before (core):** a completed `AddListener`/`AddOnce`/
  `RemoveListener`/`Reset` **happens-before** any emit that begins after it returns and
  observes the mutation (via the `atomic.Pointer` publish/load). Concurrent, unsynchronized
  Add-vs-Emit is race-free but may observe either pre- or post-state. The library
  synchronizes only its **listener set**; payload and listener-captured state are the
  caller's responsibility. *Test:* the `-race` stress/property suite (I5) plus a documented
  contract statement (see FR-9).

**Additional required test shapes (beyond the per-invariant tests above):**
- **Bound is per-signal, not per-emit (I8):** P concurrent emitters on one bounded signal;
  an instrumented max-concurrency counter must stay ≤ N.
- **`TryEmit` aggregation (I10):** k-of-n handlers fail ⇒ the joined error unwraps
  to **exactly** those k (`errors.Is` each + count); collection is race-free under `-race`;
  join order is **deterministic by registration index** (see FR-7); all-succeed ⇒ `nil`.
- **Multi-sink `OnError` fan-out (I11):** M sinks × K failing handlers ⇒ **each** sink
  observes all K errors (set equality), and one slow/panicking sink does not starve others.
- **Reentrancy:** a handler that, during its own invocation, calls
  Add/Remove/Reset/Emit/AddOnce on the same signal — no panic/deadlock; the in-flight
  emission sees its original snapshot; `Len` consistent afterward. (Reentrant `TryEmit`
  on a *bounded* signal is the known self-deadlock — covered by a test asserting the
  documented behavior, released via the ctx-deadline of I-liveness below.)
- **Liveness on a hung handler:** `TryEmit`/`TryEmit` with a never-returning
  handler and a deadline ctx must unblock at the deadline (see FR-7 ctx-liveness).
- **Negative-input matrix:** nil listener (panics at the registration call site), nil ctx
  (treated as background), nil `OnError` sink, nil `SignalOptions`, `MaxConcurrent < 0` —
  every public method, asserting the documented behavior.

#### 8.2 Property-based tests

- Long, pseudo-random operation streams (`math/rand` with **fixed seeds** for
  reproducibility, or `testing/quick`) over add/remove/emit/reset, checked against an
  independent in-test model after every step.
- Must cover I1–I4 precisely (model equality) and exercise I6.
- Minimum scale: ≥ several thousand operations per test; small key space to force
  duplicate/collision paths plus a unique-key variant for exact per-listener call counts.

#### 8.3 Native fuzz tests (`testing.F`, Go 1.21+)

- **Sequential model fuzzer:** drives add/remove/emit from fuzz bytes and asserts the
  count invariant (I1) against a model; edge cases (0, 1, many listeners; duplicate add;
  remove-absent) emerge from the input space.
- **Concurrent race fuzzer:** runs the fuzz-derived stream from multiple goroutines and
  is run under `-race` to prove I5 (no race/panic/deadlock).
  - **Implementation constraint (lesson learned):** the concurrent race fuzzer targets
    the **sync** lock-free core (no goroutine fan-out). Fuzzing the **async** path under
    `-race` with many parallel fuzz workers exhausts ThreadSanitizer's memory and is a
    tooling failure, not a code defect. Async goroutine concurrency/leaks are proven by
    the stress tests (§8.4) instead.
- **Corpus discipline:** seed corpus is committed; **any fuzz-discovered failure is
  saved as a `testdata` seed and becomes a permanent regression test.**

#### 8.4 Stress tests

- **≥ 1000 goroutines** performing concurrent add/remove/emit on the lock-free core,
  bounded by iteration count (not wall-clock sleeps), run under `-race`; balanced
  add/remove must leave the signal empty (I5).
- **Async leak stress:** concurrent `TryEmit` cycles; goroutine count must return to
  baseline via **deadline-polled** checking (I12).
- Stress tests are `-short`-skippable so the default `go test` stays fast, but run in CI.

#### 8.5 Quality gates (all required)

- `go test ./... -race` passes **100%**, including property/fuzz-seed/stress.
- Fuzz targets run **clean in CI, time-boxed** (PR: ~1 min each; nightly/extended:
  ≥ 5 min each); zero crashes.
- **No flaky timing:** synchronization via channels, `<-ctx.Done()`, and deadline
  polling — never fixed sleeps or wall-clock bounds for assertions (Windows-sensitive).
- **Coverage — RAISED BAR:** **100% line coverage on all new/changed code** in the phase.
  The *only* permitted gap is a genuinely unreachable line (e.g. a defensive
  `panic("unreachable")`), which must carry an inline `// coverage: unreachable — <reason>`
  comment and be listed in the phase evidence. **Global coverage must never regress** and
  trends toward 100%. (Supersedes the earlier "≈93%+" target; see the development tracker's
  Stage Gate G3.)
- **Determinism:** seeded property tests and committed fuzz corpus make every failure
  reproducible.

#### 8.6 CI integration

- Every PR runs `-race` (full suite incl. property + fuzz seed corpus + stress) on the
  **{Linux, Windows, macOS} × {Go 1.21, latest}** matrix. **Windows is mandatory** (the
  historically flaky platform); a Linux-only green does not satisfy this gate.
- A scheduled (nightly) job runs each fuzz target for an extended `-fuzztime` and fails
  on any new crash, committing the reproducer to the corpus.
- **Per-file coverage floor:** new Phase 4/5 concurrency files (dispatch, error model,
  once-wrapper) must each hold **100%** individually (documented-unreachable lines excepted) —
  the global number does not excuse an under-tested new file.

**Success Criteria (the §8 release gate):**
- Every invariant **I1–I17** has a dedicated, deterministic, committed test that passes.
- Property + fuzz (seed + extended) + stress + `-race` all green and reproducible.
- Coverage 100% on new code (documented exceptions only); no flaky timing assertions; fuzz
  corpus committed.
- Until all of the above are green, v1.4 **must not** be described as "robust",
  "mission-critical", or "battle-tested" in any doc, README, or release note.

### 9. Concurrency & Memory-Model Contract (the public guarantees)
**Priority:** HIGH
**Status:** Partly implicit in code today — must be **stated explicitly** in godoc + README
for v1.4 (a mission-critical user must be able to *cite* these, not infer them).

A signaling primitive that calls itself mission-critical must publish its concurrency
contract. The following are normative and must appear in godoc; each is proven by the
FR-8 invariant noted.

- **Happens-before (I17):** a completed `AddListener`/`AddOnce`/`RemoveListener`/`Reset`
  happens-before any emit that begins afterward and observes it. The library synchronizes
  only its **listener set**; payload contents and listener-captured state are the caller's
  responsibility.
- **Readers never block writers or each other:** `Emit`/`TryEmit`/dispatch reads are
  lock-free (single atomic load) and never block on a concurrent writer — a guaranteed
  liveness property, not merely a performance note. Writers are strictly serialized by the
  write mutex; the slice swap and keyed-map mutation are jointly atomic w.r.t. other
  writers (no lost updates; map and slice always consistent).
- **Ordering (I15):** sync = current-slice order (= registration order only until the first
  `RemoveListener`); async = unspecified. Stated normatively, not as an aside.
- **Reentrancy & visibility:** a listener may safely Add/Remove/Reset/Emit/AddOnce on the
  same signal during its own invocation. The in-flight emission iterates the
  previously-published immutable snapshot, so such mutations affect only **subsequent**
  emissions, never the current one. (Exception: reentrant `TryEmit` on a *bounded*
  signal can self-deadlock — see FR-7 A5.)
- **Nil inputs (fail-fast where it's a bug, tolerate where it's a mode):** a nil listener
  to any `Add*` method **panics at the call site** (fail-fast, not a deferred
  background-goroutine nil-deref). A nil `ctx` is permitted and means "no cancellation /
  no deadline" and is passed through to listeners unchanged; `context.Background()` is
  recommended over nil. `SetPanicHandler(nil)` and a nil `OnError` sink discard. A negative
  `MaxConcurrent` is treated as unset (unbounded).
- **Payload opacity:** payloads of type `T` are never inspected; the zero value (including a
  nil pointer/interface) is a valid payload and delivered unmodified.
- **Key contract:** `Keys()` never contains the empty string or internal/auto keys;
  `HasKey("")` always returns `false`; unkeyed listeners are invisible to all key-based
  APIs (consistent with the FR-4 `RemoveListener("")` fix).

**Success Criteria:**
- All bullets above are in godoc and the README concurrency section; each maps to a passing
  FR-8 invariant/test; the negative-input matrix (FR-8) covers the nil cases.

## Non-Functional Requirements

### Testing & Quality
The full, authoritative verification standard is **FR-8 (§8.1–§8.6)** — the
property/fuzz/stress proof gate that every invariant must pass before v1.4 may be
called robust. The points below are the baseline that §8 builds on:
- **Race detection**: `go test ./... -race` passes 100% (unit + property + fuzz-seed +
  stress).
- **Proof, not assumption**: every correctness invariant (FR-8 I1–I12) is backed by a
  dedicated, deterministic, committed test; fuzz-discovered failures become permanent
  regression seeds.
- **No flaky timing tests**: prefer channels, `<-ctx.Done()`, and deadline polling
  over fixed sleeps / wall-clock bounds (these were flaky on Windows).
- **Coverage**: 100% on new/changed code (documented-unreachable excepted); global never
  regresses, trends to 100% (FR-8 §8.5).
- **No leaks**: goroutine/memory leak tests pass with a polled deadline.
- **Honesty gate**: no doc, README, or release note may call v1.4 "robust",
  "mission-critical", or "battle-tested" until FR-8's gate is fully green.

### Compatibility & Portability
- **Backward compatibility**: *Not* 100%. v1.4.0 ships **two** breaks, both documented:
  1. **Runtime break (silent):** `AsyncSignal.Emit` is now fire-and-forget — code compiles,
     behavior changes; callers relying on the old blocking `Emit` must switch to
     `TryEmit`.
  2. **Source break (compile-time):** v1.4 **adds methods to the exported `Signal[T]`
     interface** — `AddOnce`, `AddOnceWithKey`, `Keys`, `HasKey` (Phase 3), and Phase 4
     adds `AddListenerWithErr`. **Any external type that implements `Signal[T]` will fail to
     compile** until it adds these methods. *(The earlier doc claim "all other v1.3.x usage
     compiles" was false and is corrected here.)*
- **Interface-break decision & mitigation:** accepted because (a) the universe of external
  `Signal[T]` implementers for an in-process library is near-zero, and (b) the additions are
  purely additive. Mitigation considered and **must be decided before release**: either
  (i) accept the break and call it out as loudly as the `Emit` break, or (ii) keep
  `Signal[T]` frozen and put the new methods on a separate extension interface
  (`KeyedSignal` / `OnceSignal`). Record the decision here.
- **Interface surface boundary (must be documented):** not all methods are on `Signal[T]`.
  `TryEmit` is sync-only; `TryEmit`/`TryEmit`/`OnError` are async-only;
  `AddListenerWithErr` is concrete (Phase 4 promotes it). The spec/godoc must state exactly
  which methods are polymorphic via `Signal[T]` vs. require a concrete type, so callers know
  the (intentionally narrow) polymorphic contract.
- **Versioning**: released as **v1.4.0** (minor). A `/v2` bump was considered and rejected —
  module-path churn disproportionate to the migration. **Both** breaks above (runtime +
  interface-extension) are weighed: adding interface methods is the "allowed but caveated"
  category in Go's compatibility guidance, and the runtime break is a one-line migration —
  so a prominent callout in a minor is judged acceptable. (Documented SemVer deviation;
  H4 tracks revisiting the policy, now covering **both** break categories.)
- **Go version**: requires **Go 1.21+** (per `go.mod`).
- **CI platform matrix (mandatory):** CI runs **{Linux, Windows, macOS} × {Go 1.21,
  latest}**, all with `-race` + the stress/property suites. **Windows is required, not
  optional** — it is the platform whose scheduler historically exposed the timing flakiness
  this release fixes; a green Linux-only run does **not** satisfy the FR-8 gate.
- **Zero external dependencies**: core library remains dependency-free (also a supply-chain
  property: no third-party code in the trust boundary).

### Documentation
- Godoc for all public APIs; README quick start + migration note; honest benchmark
  guidance (how to run them) rather than headline numbers.

## Out of Scope for v1.4 (Deferred)

Lock-free copy-on-write (FR-0), the async worker pool (FR-7, as the semaphore-based
*safety valve* per [ADR 0001](docs/design/0001-async-dispatch-and-error-model.md)), and
property/fuzz/stress testing (FR-8) are all **in scope** for v1.4.

**Deferred to v1.5+ (observability):**
- **Metrics**: `Stats()`, `Metadata()`, optional Prometheus exporter — its own release;
  keeps the v1.4 core lean.

### Future Hardening (post-v1.4) — the path beyond A+

These items raise the signaling primitive from "proven robust under normal + concurrent
load" (the v1.4 A+ bar) toward "robust under *adversarial* load." They are deliberately
**not** in v1.4 to keep the default simple and correct, but are tracked here so the path
is explicit. Each is an **opt-in**, never a default that could surprise existing code.

- **H1 — Opt-in hard-bound mode (overflow policy).** A bounded pending-work queue with
  an explicit `OverflowPolicy` (`DropNewest` / `Block` / `Error`) plus an `OnOverflow`
  hook, for environments where *sustained/adversarial* overload must be survived with a
  **hard memory ceiling** (DoS resistance). Closes the v1.4 caveat that the dispatcher
  bounds *execution* but not the *backlog* (parked work can grow without limit under
  sustained overload). This is the work the pattern catalog tags **🔭 post-v1.4**.
- **H2 — Hung/slow-handler detection.** A per-handler slot watchdog that surfaces (via
  the panic/error sink or a metric) handlers exceeding a deadline — so a stuck listener
  holding a bounded slot is *visible*, not silent. Go cannot forcibly kill a goroutine,
  so this is detection/reporting, not cancellation.
- **H3 — Starvation detection.** Under a configured `MaxConcurrent`, detect and surface
  the case where long-running listeners hold all slots and never-started listeners are
  starved — turning the documented A5 risk into an observable signal.
- **H4 — SemVer policy revisit.** Re-evaluate whether future runtime-breaking changes
  warrant a `/v2` module path rather than a prominent-callout-in-minor (the v1.4
  documented deviation), now that the precedent exists.

See [v1.5-plus.requirements.md](v1.5-plus.requirements.md).

## Migration Path from v1.3.x

```go
// Existing v1.3 code that DID NOT rely on Emit blocking — no change needed:
sig := signals.New[Event]()
sig.AddListener(listener, "key")
sig.Emit(ctx, event) // still valid; now returns immediately

// BREAKING: if you relied on Emit waiting for all listeners, switch to TryEmit:
// Before (v1.3): sig.Emit(ctx, event)   // blocked until listeners finished
// After  (v1.4):
sig.TryEmit(ctx, event)              // concurrent listeners, blocks until done

// NEW in v1.4: configure panic reporting for async listeners
signals.SetPanicHandler(func(recovered any) {
    log.Printf("listener panic: %v", recovered)
})

// NEW in v1.4: one-time listeners
sig.AddOnce(listener)
sig.AddOnceWithKey(listener, "once-key")

// NEW in v1.4: key introspection
if sig.HasKey("my-key") {
    _ = sig.Keys()
}

// NEW in v1.4: bounded async dispatch (opt-in; unbounded by default).
// Bounds CONCURRENT handlers via a counting semaphore; excess parks (never dropped,
// caller never blocked). Only bound when your listeners are short-lived (a bound can
// starve long-running listeners). signals.DefaultMaxConcurrent() = 2*NumCPU is recommended.
sig := signals.NewWithOptions[Event](&signals.SignalOptions{
    MaxConcurrent: 100,
})
```

> `Stats()` / `Metadata()` from the original draft do **not** exist in v1.4 — metrics are
> deferred to v1.5. `MaxConcurrent` **is** in v1.4 (see FR-7).
