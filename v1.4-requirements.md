# Version 1.4 Requirements

> **Status:** This document reflects the agreed v1.4.0 direction: the
> correctness work from [PR #14](https://github.com/maniartech/signals/pull/14)
> (partially accepted) **plus** a proper lock-free rewrite that restores a
> *verifiable* performance story. PR #14 fixed real bugs but deviated from the
> project's goal by removing the performance machinery and its claims wholesale.
> Rather than drop performance, v1.4 keeps PR #14's correctness fixes and rebuilds
> speed the honest way — lock-free copy-on-write plus a real async worker pool,
> benchmarked before any claim is written, and verified with property + fuzz testing.
> **Only metrics/observability is deferred to v1.5+**
> (see [v1.5-plus.requirements.md](v1.5-plus.requirements.md)).
> The authoritative changelog is [RELEASENOTES.md](RELEASENOTES.md).

## Objectives

Version 1.4 is a **correctness + verified-performance release**: fix the behavioral
bugs found during audit, make the async/sync contracts honest and predictable, replace
the removed performance machinery with a lock-free copy-on-write core, and document the
library as it actually behaves — with every performance number backed by a committed,
reproducible benchmark.

**Philosophy**: Ship something correct, honest, *and* fast. PR #14's lesson was not
"performance is bad" — it was "don't ship claims you can't reproduce." So v1.4 keeps
the correctness fixes, rebuilds performance via lock-free copy-on-write, and lets
`benchstat` output — not marketing — decide what the README is allowed to claim.

> ⚠️ **v1.4.0 contains a breaking runtime change.** `AsyncSignal.Emit` is now truly
> fire-and-forget (returns immediately). Code still compiles, so the change is
> silent — callers who relied on the old blocking behavior must switch to
> `EmitAndWait`. See [RELEASENOTES.md](RELEASENOTES.md) and the README migration note.

### Primary Goals

0. **Lock-free copy-on-write core**: replace `sync.RWMutex` with an immutable listener
   slice behind `atomic.Pointer`, writers serialized by a mutex (lock-free reads,
   locked writes). Eliminates the per-emit snapshot copy and reader contention.
   Performance claims gated on measured before/after numbers.

1. **Correct, honest semantics**: `AsyncSignal.Emit` is fire-and-forget;
   `SyncSignal.Emit` invokes error-returning listeners (discarding errors);
   `TryEmit` stops on first error/cancel. Canceled contexts skip all listeners.

2. **Zero-value safety**: `var sig signals.SyncSignal[int]` / `AsyncSignal[int]`
   is usable without a constructor (lazy `sync.Once` init).

3. **Bug fixes**: keyed removal no longer drops unkeyed listeners; `GrowthFunc` is
   actually honored (was dead code); race/staticcheck findings resolved.

4. **Safe escape hatch + panic policy**: `EmitAndWait` for callers that need the old
   blocking behavior; `SetPanicHandler` replaces silent `recover()`.

5. **API ergonomics (small, low-risk)**: `AddListenerWithErr` on async (done),
   one-time listeners (`AddOnce`/`AddOnceWithKey`), and key introspection
   (`Keys`/`HasKey`).

6. **Documentation that matches reality**: README, godoc, and release notes describe
   actual behavior; the migration path from v1.3.x is documented honestly.

7. **Configurable async worker pool**: reintroduce `SignalOptions.WorkerPoolSize` with a
   real goroutine pool for `AsyncSignal` (replacing goroutine-per-listener) — the lever
   for async throughput, since lock-free only helps the sync path. Benchmarked.

8. **Verified concurrency**: property-based + native fuzz testing of the lock-free core,
   on top of race + stress coverage, to prove the rewrite's invariants.

### Explicitly NOT in v1.4 (moved to v1.5+)

- **Metrics**: `Stats()`, Prometheus exporter, `Metadata()` introspection — observability
  is its own release; the v1.4 core stays lean. (This is the *only* item deferred to
  v1.5; lock-free, worker pool, and property/fuzz testing are all in v1.4.)

### Target Outcomes

#### Correctness Goals
- **No race conditions**: 100% pass with `-race` across all existing tests
- **No resource leaks**: goroutine and memory leak tests pass
- **Panic isolation**: a listener panic never crashes other listeners; recovery is
  routed through `SetPanicHandler`
- **Specified semantics**: every emit/cancel/error path documented and tested

#### Usability Goals
- **Honest API**: behavior of `Emit` / `EmitAndWait` / `TryEmit` clearly documented
- **Better errors**: `AddListenerWithErr` works on both sync and async signals
- **Ergonomic additions**: `AddOnce`, `Keys`, `HasKey`

#### Quality Goals
- **High coverage**: maintain the existing coverage level (≈93%+); do not regress
- **Documented migration**: clear v1.3.x → v1.4.0 upgrade note covering the breaking
  `Emit` change

### What's New / Changed in v1.4

**Semantics (breaking + behavioral):**
- `AsyncSignal.Emit` is fire-and-forget (returns immediately) — **breaking**
- `SyncSignal.Emit` now invokes error-returning listeners (errors discarded)
- Canceled context ⇒ both `Emit` variants skip all listeners

**Added:**
- `AsyncSignal.EmitAndWait(ctx, payload)` — concurrent listeners, blocks until done
- `signals.SetPanicHandler(func(recovered any))` — configurable panic reporting
- `AddListenerWithErr` promoted to the `Signal` interface / implemented on async
- One-time listeners: `AddOnce()`, `AddOnceWithKey()`
- Key introspection: `Keys()`, `HasKey()`

**Fixed:**
- `RemoveListener("")` no longer removes unkeyed listeners (new `keyed` flag)
- `SignalOptions.GrowthFunc` is now actually used during growth
- Race / staticcheck findings in tests

**Removed:**
- Worker pool, `sync.Pool`, single-listener fast path, and the sub-10ns / zero-alloc
  claims that depended on them. Async emit now allocates (a goroutine per listener).

**Future versions:** Worker-pool configuration and observability are tracked in
[v1.5-plus.requirements.md](v1.5-plus.requirements.md).

## Functional Requirements

### 0. Lock-Free Copy-on-Write Core
**Priority:** HIGH
**Status:** Not Implemented (0%) — the defining engineering work of v1.4

**Current State:** `BaseSignal` guards `[]keyedListener[T]` with `sync.RWMutex`; every
`Emit`/`TryEmit`/`dispatch` takes an `RLock` and copies the slice into a snapshot before
iterating (see `signals_sync.go`, `signals_async.go`). The copy cost is paid on the hot
*read* path.

**Target:** Store listeners as an **immutable** slice behind `atomic.Pointer[[]keyedListener[T]]`.
Reads (Emit) do a single atomic load and iterate directly — no lock, no copy, no alloc.
Writes (Add/Remove/Reset) take a `sync.Mutex`, build a new slice, and atomically swap it
in (copy-on-write). This is "lock-free reads, locked writes" — **not** full CAS-loop
lock-free; do not attempt the latter.

**Requirements:**
- Replace the `RWMutex` + per-emit snapshot with `atomic.Pointer` + write-mutex COW.
- Preserve all existing semantics byte-for-byte: ordering, keyed dedup map, `keyed`
  flag, `GrowthFunc` behavior, zero-value safety, context/cancel rules.
- Public API unchanged; all existing tests pass unmodified.
- The keyed-dedup map must stay consistent with the swapped slice (rebuild or guard
  under the write mutex).

**Success Criteria (gate every perf claim on these):**
- `go test ./... -race` passes 100%.
- `benchstat` shows the sync single-listener path improves (target ~10–12 ns, 0 alloc;
  measured, not assumed) and the multi-listener path drops its per-emit allocation.
- A new concurrent-sync benchmark demonstrates near-linear scaling vs the RWMutex
  baseline at 2/4/8/16 cores.
- **Honesty rule:** no performance number reaches the README until it is produced by a
  committed benchmark and reproducible via `go test -bench`. Async numbers must be
  labeled as dispatch rate (goroutine-per-listener), not listener completion.

### 1. Correct Emit / Cancel / Error Semantics
**Priority:** HIGH
**Status:** Implemented ✅ (PR #14 + maintainer fixes)

**Requirements:**
- `AsyncSignal.Emit` schedules each listener in its own goroutine and returns
  immediately (does not wait).
- `AsyncSignal.EmitAndWait` schedules listeners concurrently and blocks until all
  complete.
- `SyncSignal.Emit` invokes both plain and error-returning listeners, discarding any
  returned errors.
- `SyncSignal.TryEmit` invokes listeners sequentially and stops on the first error or
  canceled context, returning that error.
- A context that is already canceled causes all `Emit`/`EmitAndWait`/`TryEmit`
  variants to skip every listener.

**Success Criteria:**
- Each rule above is covered by a dedicated, non-flaky test (no fixed-sleep / wall-clock
  assertions; use channels, `<-ctx.Done()`, polling with deadlines).
- `go test ./... -race` passes.

### 7. Configurable Async Worker Pool
**Priority:** MEDIUM
**Status:** Not Implemented (0%)

**Current State:** `AsyncSignal.dispatch` spawns one goroutine **per listener per emit**
(`signals_async.go`). This is the dominant async cost and bounds async throughput; the
lock-free core (FR-0) does not address it.

**Target:** A real, bounded worker pool for async emission, configured via a new
`SignalOptions.WorkerPoolSize` field.

```go
type SignalOptions struct {
    InitialCapacity int                // existing
    GrowthFunc      func(int) int      // existing
    WorkerPoolSize  int                // NEW: async worker pool size
}
```

**Requirements:**
- Add `WorkerPoolSize` to `SignalOptions`; default `2 * runtime.NumCPU()`.
- Async emission dispatches listener work onto the pool instead of `go func()` per
  listener. `EmitAndWait` still blocks until the emitted batch completes.
- Preserve fire-and-forget `Emit` semantics, panic recovery via `SetPanicHandler`, and
  context-cancel behavior.
- No goroutine leaks; pool shuts down cleanly on `Reset`/GC as appropriate.

**Success Criteria:**
- `benchstat` shows reduced allocations / improved throughput on the async multi-listener
  path vs the goroutine-per-listener baseline.
- Pool size is documented with sizing guidance; default works out of the box.
- `-race` clean; no goroutine leaks under the stress test.

#### Prior art: why a pool existed, why PR #14 removed it, why we bring it back

**A pool existed on `master`** (removed in PR #14 commit `746bcd5`): `AsyncSignal.Emit`
used a bounded `workerPool chan *emitTask`, a `sync.Pool` for snapshot/task reuse, and a
single-listener "zero-allocation fast path" — all to support the old README's
*"sub-10ns, zero-allocation"* claims.

**PR #14 was right to remove *that* pool.** Its removal reasoning (reconstructed from the
diff + commit titles; the PR wrote no long justification):
1. **It blocked.** The old `Emit` ended with `wg.Wait()` and a *bounded* channel send
   (`s.workerPool <- task`) blocks the caller when saturated — fundamentally incompatible
   with the new fire-and-forget `Emit`.
2. **Deadlock risk** — commit `9187cd9` ("Fix sync deadlock risk and async snapshot");
   bounded channel + reentrant emits could wedge.
3. **The claim it served was false** — async allocates inherently (goroutine per
   listener); the audit tests (`0c05756`) proved the "zero-alloc" story didn't hold.
4. **Lifecycle complexity** — `sync.Once` init, two `sync.Pool`s, a size threshold, and
   GC-based shutdown, versus a trivial `go func()`.

**Strong reasons to reintroduce a pool in v1.4 (a *different*, fire-and-forget-native one):**
1. **Unbounded goroutines = no backpressure = the #1 production failure mode.** Today a
   fast emitter with slow listeners spawns goroutines without limit — memory blows up and
   the scheduler thrashes under load. This is the classic event-system outage. A bounded
   pool is the *only* control point that prevents it. For a library positioned at
   HFT/real-time/embedded, "spawn as many goroutines as the load demands" is a
   non-starter — those domains require **bounded, predictable** resource use.
2. **It is the async performance lever.** Lock-free (FR-0) speeds the *sync* path and does
   nothing for async, where goroutine spawn + stack alloc + closure per listener per emit
   dominates. A pool with recycled workers and a work queue **amortizes** that — the only
   way async throughput improves. This is what makes the v1.4 performance story complete
   rather than sync-only.
3. **Operator control.** `WorkerPoolSize` lets users tune concurrency to their workload
   (CPU-bound vs IO-bound listeners) instead of being at the mercy of fan-out × emit-rate.
4. **It restores the capability honestly.** Same outcome the old pool promised (bounded,
   efficient async dispatch) — but earned by a benchmark and built to be non-blocking and
   deadlock-free, not propping up a false zero-alloc claim.

**Hard design constraints (the mistakes we must NOT repeat):**
- **Dispatch must never block `Emit`** — when the pool/queue is saturated, apply an
  explicit policy (bounded queue with documented overflow behavior), not a blocking
  channel send.
- **Reentrancy-safe** — a listener that emits on the same signal must not deadlock.
- **Deterministic shutdown** — explicit lifecycle tied to `Reset`/close, not a GC
  finalizer.
- **Must beat goroutine-per-listener on a committed benchmark**, or it does not ship.

### 8. Verified Concurrency — the Proof Standard (Property + Fuzz + Stress)
**Priority:** HIGH (this is what earns the "robust" claim)
**Status:** Partial (40%) — race + concurrent benchmarks exist; property/fuzz/stress not yet

**Principle:** *Robustness is not designed in, it is proven.* No invariant of the
lock-free core or the async dispatcher may be *assumed*; each must be **mechanically
verified** by a committed test that an adversary (fuzzer, race detector, stress load)
has tried and failed to break. A claim of "military-grade / mission-critical
robustness" for the signaling primitive is earned **only** when every item in this
section is green and reproducible in CI — not before. This is the same honesty rule
applied to performance (FR-0), now applied to correctness.

This section is the authoritative definition of "proven" for v1.4. It is a **hard
release gate**: v1.4.0 does not tag until §8 passes in full.

#### 8.1 Invariants that MUST be proven

Every invariant below must have at least one dedicated, deterministic test. Invariants
marked **(core)** apply to the lock-free copy-on-write core (FR-0, built); those marked
**(async)** apply to the dispatcher + error model (FR-7/ADR 0001, to be built).

- **I1 — Count integrity (core):** `Len()` always equals the number of live
  registrations; duplicate keyed add returns `-1` and is a no-op; removing an absent
  key returns `-1` and is a no-op.
- **I2 — Introspection consistency (core):** `HasKey(k)` and `Keys()` agree with the
  set of live keyed listeners at every step (internal/auto keys and empty keys omitted
  from `Keys()`).
- **I3 — No-call-after-remove (core):** once removed, a listener is never invoked by any
  subsequent emission.
- **I4 — All-live-receive (core):** every emission invokes exactly the set of
  currently-live listeners — no misses, no extras, no duplicates.
- **I5 — No corruption under concurrency (core):** arbitrary concurrent
  add/remove/emit/reset interleavings never race, panic, deadlock, or corrupt state.
- **I6 — Exactly-once (async/core):** an `AddOnce` listener fires exactly once even
  under many simultaneous emissions, then auto-removes.
- **I7 — Panic isolation (async):** a panicking handler never crashes the process and
  never prevents sibling handlers from running; the recovered value reaches the
  configured `SetPanicHandler`.
- **I8 — Bounded concurrency (async):** with `WorkerPoolSize = N`, at most `N` handler
  goroutines run concurrently across all in-flight emissions; with no pool, dispatch is
  unbounded and **never starves** a listener.
- **I9 — Fire-and-forget integrity (async):** `Emit` returns without waiting for
  handler completion in all configurations (pool or no pool).
- **I10 — Wait/aggregate correctness (async):** `EmitAndWait` returns only after all
  handlers of that emission complete; `EmitAndWaitErr` returns the `errors.Join` of
  every handler error and `nil` iff all succeeded.
- **I11 — Error routing (async):** an error returned by an `AddListenerWithErr` handler
  on the `Emit` path reaches every registered `OnError` sink; none are dropped silently.
- **I12 — No goroutine/memory leak (async):** after emissions quiesce, goroutine count
  returns to baseline and memory does not grow unbounded across repeated cycles.

#### 8.2 Property-based tests

- Long, pseudo-random operation streams (`math/rand` with **fixed seeds** for
  reproducibility, or `testing/quick`) over add/remove/emit/reset, checked against an
  independent in-test model after every step.
- Must cover I1–I4 precisely (model equality) and exercise I6.
- Minimum scale: ≥ several thousand operations per test; small key space to force
  duplicate/collision paths plus a unique-key variant for exact per-listener call counts.

#### 8.3 Native fuzz tests (`testing.F`, Go 1.21+)

- **Sequential model fuzzer:** drives add/remove/emit from fuzz bytes and asserts the
  count invariant (I1) against a model; edge cases (0, 1, many listeners; duplicate add;
  remove-absent) emerge from the input space.
- **Concurrent race fuzzer:** runs the fuzz-derived stream from multiple goroutines and
  is run under `-race` to prove I5 (no race/panic/deadlock).
  - **Implementation constraint (lesson learned):** the concurrent race fuzzer targets
    the **sync** lock-free core (no goroutine fan-out). Fuzzing the **async** path under
    `-race` with many parallel fuzz workers exhausts ThreadSanitizer's memory and is a
    tooling failure, not a code defect. Async goroutine concurrency/leaks are proven by
    the stress tests (§8.4) instead.
- **Corpus discipline:** seed corpus is committed; **any fuzz-discovered failure is
  saved as a `testdata` seed and becomes a permanent regression test.**

#### 8.4 Stress tests

- **≥ 1000 goroutines** performing concurrent add/remove/emit on the lock-free core,
  bounded by iteration count (not wall-clock sleeps), run under `-race`; balanced
  add/remove must leave the signal empty (I5).
- **Async leak stress:** concurrent `EmitAndWait` cycles; goroutine count must return to
  baseline via **deadline-polled** checking (I12).
- Stress tests are `-short`-skippable so the default `go test` stays fast, but run in CI.

#### 8.5 Quality gates (all required)

- `go test ./... -race` passes **100%**, including property/fuzz-seed/stress.
- Fuzz targets run **clean in CI, time-boxed** (PR: ~1 min each; nightly/extended:
  ≥ 5 min each); zero crashes.
- **No flaky timing:** synchronization via channels, `<-ctx.Done()`, and deadline
  polling — never fixed sleeps or wall-clock bounds for assertions (Windows-sensitive).
- **Coverage ≥ 93%** maintained; new code paths covered.
- **Determinism:** seeded property tests and committed fuzz corpus make every failure
  reproducible.

#### 8.6 CI integration

- Every PR runs `-race` (full suite incl. property + fuzz seed corpus + stress) on
  Go 1.21 and latest.
- A scheduled (nightly) job runs each fuzz target for an extended `-fuzztime` and fails
  on any new crash, committing the reproducer to the corpus.

**Success Criteria (the §8 release gate):**
- Every invariant I1–I12 has a dedicated, deterministic, committed test that passes.
- Property + fuzz (seed + extended) + stress + `-race` all green and reproducible.
- Coverage ≥ 93%; no flaky timing assertions; fuzz corpus committed.
- Until all of the above are green, v1.4 **must not** be described as "robust",
  "mission-critical", or "battle-tested" in any doc, README, or release note.

## Implementation Roadmap (Phases)

Ordered path from the current state to a released v1.4.0. Each phase has a hard exit
gate; do not start a phase until the previous gate is green. Measurement comes **before**
optimization so every performance claim has a real before/after.

**Current state:** PR #14 + maintainer fixes live on branch `pr-14-fixes` (correctness
fixes, `EmitAndWait`, `SetPanicHandler`, async `AddListenerWithErr` — all ✅). Not yet
merged. Still to build: lock-free core, `AddOnce`/`Keys`/`HasKey`, async worker pool,
property/fuzz suites, sync benchmarks, CI.

### Phase 0 — Land PR #14 & reconcile docs
**Goal:** Get the correctness foundation onto `master` with Joshua credited; align docs.
- Commit the doc changes (README breaking-change callout, RELEASENOTES, this doc).
- Post the partial-acceptance comment to PR #14.
- Merge `pr-14-fixes` → `master` with `--no-ff` (Joshua's 5 commits byte-for-byte; **no
  squash, no rebase**).
- **Gate:** PR #14 shows "Merged" on GitHub; `go test ./... -race` green on `master`.

### Phase 1 — CI + benchmark baseline (measure first)
**Goal:** Lock in a reproducible "before" and stop shipping blind.
- Add GitHub Actions: `go test -race`, `go vet`, `gofmt -l`, `go test -bench=. -benchmem`
  (Go 1.21 + latest). Note: existing CircleCI uses Go 1.18 but `go.mod` needs 1.21.
- Add the **missing sync benchmarks**: `BenchmarkSyncEmit_SingleListener`,
  `_TenListeners`, and a new `_Concurrent` (RunParallel) — the headline path is
  currently unmeasured.
- Record baseline `benchstat` output (RWMutex) as the comparison point.
- **Gate:** CI green on `master`; baseline numbers committed (e.g. `bench/baseline.txt`).

### Phase 2 — Lock-free copy-on-write core (FR-0)
**Goal:** Replace RWMutex + per-emit snapshot with `atomic.Pointer` + write-mutex COW.
- Rework `BaseSignal`: immutable slice behind `atomic.Pointer`; Add/Remove/Reset build
  and atomically swap; keep keyed-dedup map consistent under the write mutex.
- Rewrite `Emit`/`TryEmit`/`dispatch` read paths to a single atomic load (no lock, no copy).
- Preserve all semantics; **all existing tests pass unmodified**.
- Run `benchstat baseline.txt new.txt`.
- **Gate:** `-race` 100%; API unchanged; sync single-listener improves (target ~10–12 ns,
  0 alloc, *measured*); concurrent-sync shows near-linear scaling vs baseline.

### Phase 3 — API quick wins
**Goal:** Ship the agreed ergonomic additions on top of the lock-free core.
- `AddOnce` / `AddOnceWithKey` — fire exactly once then auto-remove (atomic one-shot
  guard so concurrent emits can't double-fire).
- `Keys()` (snapshot, concurrent-safe) / `HasKey()` (O(1)).
- Promote all to the `Signal` interface; implement on sync + async; full tests incl. a
  concurrent exactly-once test for `AddOnce`.
- **Gate:** new APIs tested, documented, zero overhead when unused; `-race` green.

### Phase 4 — Async worker pool (FR-7)
**Goal:** Give async a real throughput lever (lock-free only helped sync).
- Add `SignalOptions.WorkerPoolSize` (default `2 * runtime.NumCPU()`); dispatch async
  listener work onto a bounded pool instead of `go func()` per listener.
- Preserve fire-and-forget `Emit`, `EmitAndWait` blocking, panic recovery, cancel rules.
- Benchstat async multi-listener vs the goroutine-per-listener baseline.
- **Gate:** improved async throughput/allocs (measured); no goroutine leaks; `-race` green.
  Can run in parallel with Phase 3.

### Phase 5 — Concurrency verification (FR-8)
**Goal:** Prove the lock-free core + pool under adversarial concurrency.
- Property-based tests for the lock-free invariants (count, no-call-after-remove, all
  live listeners fire, no corruption).
- Native `testing.F` fuzz target over concurrent add/remove/emit (time-boxed in CI).
- Stress test: 1000+ goroutines, deadline-polled; goroutine + memory leak checks.
- **Gate:** property + fuzz + stress pass repeatably; `-race` 100%; coverage ≈93%+ held;
  no flaky timing assertions.

### Phase 6 — Honest benchmarks, docs & claims
**Goal:** Turn measured numbers into reproducible README claims.
- Finalize benchmark suite; write real numbers into README **with conditions** (signal

## Non-Functional Requirements

### Testing & Quality
The full, authoritative verification standard is **FR-8 (§8.1–§8.6)** — the
property/fuzz/stress proof gate that every invariant must pass before v1.4 may be
called robust. The points below are the baseline that §8 builds on:
- **Race detection**: `go test ./... -race` passes 100% (unit + property + fuzz-seed +
  stress).
- **Proof, not assumption**: every correctness invariant (FR-8 I1–I12) is backed by a
  dedicated, deterministic, committed test; fuzz-discovered failures become permanent
  regression seeds.
- **No flaky timing tests**: prefer channels, `<-ctx.Done()`, and deadline polling
  over fixed sleeps / wall-clock bounds (these were flaky on Windows).
- **Coverage**: maintain ≈93%+ line coverage; do not regress.
- **No leaks**: goroutine/memory leak tests pass with a polled deadline.
- **Honesty gate**: no doc, README, or release note may call v1.4 "robust",
  "mission-critical", or "battle-tested" until FR-8's gate is fully green.

### Compatibility & Portability
- **Backward compatibility**: *Not* 100%. v1.4.0 intentionally changes
  `AsyncSignal.Emit` semantics at runtime. This is the one documented break; all other
  v1.3.x usage compiles and behaves unchanged.
- **Versioning**: released as **v1.4.0** (minor). A formal SemVer-major (`/v2`) bump
  was considered and rejected — Go's major-version module-path mechanism imposes
  import churn disproportionate to a one-line migration. The break is called out
  prominently instead. (Documented deviation from strict SemVer; revisit the policy
  for future breaks.)
- **Go version**: requires **Go 1.21+** (per `go.mod`). CI should test 1.21 and latest.
- **Zero external dependencies**: core library remains dependency-free.

### Documentation
- Godoc for all public APIs; README quick start + migration note; honest benchmark
  guidance (how to run them) rather than headline numbers.

## Migration Path from v1.3.x

```go
// Existing v1.3 code that DID NOT rely on Emit blocking — no change needed:
sig := signals.New[Event]()
sig.AddListener(listener, "key")
sig.Emit(ctx, event) // still valid; now returns immediately

// BREAKING: if you relied on Emit waiting for all listeners, switch to EmitAndWait:
// Before (v1.3): sig.Emit(ctx, event)   // blocked until listeners finished
// After  (v1.4):
sig.EmitAndWait(ctx, event)              // concurrent listeners, blocks until done

// NEW in v1.4: configure panic reporting for async listeners
signals.SetPanicHandler(func(recovered any) {
    log.Printf("listener panic: %v", recovered)
})

// NEW in v1.4: one-time listeners
sig.AddOnce(listener)
sig.AddOnceWithKey(listener, "once-key")

// NEW in v1.4: key introspection
if sig.HasKey("my-key") {
    _ = sig.Keys()
}

// NEW in v1.4: configurable async worker pool
sig := signals.NewWithOptions[Event](&signals.SignalOptions{
    WorkerPoolSize: 100,
})
```

> `Stats()` / `Metadata()` from the original draft do **not** exist in v1.4 — metrics are
> deferred to v1.5. `WorkerPoolSize` **is** in v1.4 (see FR-7).
