## The Stage Gate (applies to EVERY phase)

No phase advances to the next until **all** of the following are green and recorded. Each
check is a single re-runnable command (idempotent — safe to run anytime).

### G1 — Build & hygiene
```bash
go build ./... && go vet ./... && gofmt -l . | tee /dev/stderr | (! read)
```
Pass = builds, vets clean, `gofmt -l` empty.

### G2 — Correctness under race
```bash
go test ./... -race -count=1
```
Pass = 100% green, including property/fuzz-seed/stress.

### G3 — Coverage (RAISED BAR: 100% on new/changed code)
```bash
# Blackbox tests live in ./tests (package signals_test); -coverpkg attributes their
# coverage back to the signals package. Whitebox tests are in root internal_test.go.
go test ./... -coverpkg=github.com/maniartech/signals -coverprofile=cover.out -covermode=atomic && go tool cover -func=cover.out | tail -1
```
Pass criteria:
- **New/changed code in this phase: 100% line coverage.** Any genuinely unreachable line
  (e.g. a defensive `panic("unreachable")`) is the **only** allowed gap and must be marked
  with an inline `// coverage: unreachable — <reason>` comment and listed in the phase's
  evidence. No other uncovered lines permitted.
- **Global coverage must not regress** and should trend toward 100%.

### G4 — Edge-case matrix (T2)
Every public entry point touched in the phase has explicit tests for: `nil` listener
(panics at call site), `nil` ctx (treated as background), already-canceled ctx (skips),
canceled-mid-flight ctx, zero-value signal, empty signal (0 listeners), 1 listener, many
listeners, duplicate key (`-1`), absent key (`-1`), empty-string key, negative
`MaxConcurrent`, zero payload. (Maps to FR-9 + FR-8 negative-input matrix.)

### G5 — Usability / scenario tests (T4)
At least the relevant **practical examples** from the [pattern catalog](patterns/) are
written as compiled, run tests — proving the API is ergonomic and correct in realistic
flows, not just unit-correct. (E.g. Phase 4 ⇒ the bounded-concurrency, async-error-routing,
result-aggregation, backpressure practical examples run as tests.)

### G6 — Invariants (FR-8) relevant to the phase
Each FR-8 invariant in the phase's scope has a dedicated, deterministic, committed test
that passes (see per-phase lists below).

### G7 — Evidence recorded
The phase's row in the Dashboard and its task block record: commit hash(es), the G3
coverage number, and any documented unreachable-line exceptions. Only then → 🔬 VERIFIED.

> **Cross-platform note:** G2/G3 must ultimately pass on **{Linux, Windows, macOS} ×
> {Go 1.21, latest}** in CI (FR-8 §8.6). Local dev may run one OS; the phase is not 🔬
> VERIFIED until CI is green on the full matrix (gated by Phase 1's OS-matrix task).

## Resume Protocol (how to recover if interrupted or broken)

1. **Locate position:** read the Dashboard; the current phase is the first non-🔬 row.
2. **Confirm no regression:** run **G1 + G2** at HEAD. If red, you are in a broken state →
   go to step 4.
3. **Find the next task:** within the current phase, the first `☐`/`◐` task is next.
4. **Recover from breakage (idempotent):**
   - Identify the last 🔬 VERIFIED commit from the Dashboard/evidence.
   - `git stash` or inspect the working tree; if the in-progress change is unsalvageable,
     `git restore` the affected files (or `git reset --hard <last-verified-commit>` **only**
     if nothing valuable is uncommitted) to return to a known-green state. Mark the task
     `↩ ROLLED-BACK` with a note.
   - Re-run G1+G2 to confirm green, then retry the task.
5. **Never advance a phase** with a red gate. A half-finished phase stays `◐ IN-PROGRESS`.
6. **One logical change per commit;** each commit message states which task ID it advances,
   so the git history is itself a recovery log.

> Idempotency rule: every gate command is safe to run repeatedly and is the **sole** source
> of truth for "is this done?" — never mark VERIFIED from memory; re-run the gate.

## Phase 4 — Bounded async dispatch + async error model (FR-7, ADR 0001)
**Goal:** implement exactly per ADR 0001, using `MaxConcurrent`. Build in small, gated steps.

### Build tasks
> **Increment 4A (bounded dispatch) — DONE & verified:** 4.1, 4.2, 4.3, 4.7 below, plus
> the `MaxConcurrent` godoc part of 4.8. `signals_bounded_dispatch_test.go` proves I8, I9,
> I13, I16, and ctx-liveness under `-race`; 100% coverage; full `-race` suite green.
> **Design fix found while building:** `Emit = go dispatch()` initially read the listener
> slice asynchronously, so a `Reset()` racing a fire-and-forget emit could make the emit
> fire nothing (and hung a leak test). Fixed by **snapshotting the listener slice at
> emit-call time**, then dispatching the snapshot in the background — intuitive "emit
> captures current listeners" semantics, still O(1) on the caller.

- [x] **4.1** — Added `SignalOptions.MaxConcurrent`; `DefaultMaxConcurrent()` (= 2×NumCPU);
  `AsyncSignal.slots chan struct{}` wired in `NewWithOptions` (nil = unbounded).
- [x] **4.2** — `Emit = go dispatch(snapshot)` / `TryEmit = dispatch + ctx-aware wait`;
  each handler in its own goroutine; semaphore acquire (with parked-cancellation) +
  `defer`-paired release.
- [x] **4.3** — per-handler panic recovery; slot released on **every** exit path incl.
  recovered panic — proven by `TestBounded_SlotReleasedOnPanic` (**I13**).
- [x] **4.4** — Wired `listenerErr` into dispatch (silent gap fixed); `AddListenerWithErr`
  on `AsyncSignal` and **promoted to the `Signal` interface** — compiled clean (no in-repo
  implementer broke); recorded in Compatibility. ← **4B**
- [x] **4.5** — `OnError(func(ctx,error))` per-signal, **multiple sinks** (COW slice behind
  atomic pointer); sinks run on the handler goroutine; a sink panic is recovered and does
  not stop the others (**B1/I11/I14**). *(Contract relaxed from "after slot release" to
  "keep sinks cheap" — a blocking sink holds its slot like a blocking listener; simpler &
  consistent; spec note pending.)*
- [x] **4.6** — `TryEmit` — race-free per-index error collection, deterministic
  registration-order `errors.Join`, nil iff all succeed, ctx-aware (returns `ctx.Err()` on
  cancel without reading the in-progress errs) (**B2/I10**).
- [x] **4.7** — ctx-liveness: `TryEmit` returns at the ctx deadline even with a hung
  handler (`waitForOrCancel`); parked-acquire cancellation (`select` on `slots` vs
  `ctx.Done()`). Proven by `TestBounded_TryEmitRespectsCtxDeadline` +
  `TestBounded_ParkedAcquireCancels`. *(TryEmit variant lands in 4B.)*
- [x] **4.8** — Godoc: backlog caveat + starvation/reentrancy (A5) on `MaxConcurrent` ✅;
  interface-surface boundary + remaining FR-9 statements ✅ (Phase 6: package-level
  `doc.go` now publishes the full concurrency / memory-model contract).
